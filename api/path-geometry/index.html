PathGeometry

Three-dimensional path authoring and differential geometry: a PathBuilder of straight, bend, catenary and helix segments, jumpto! connectors and zero-length rotator! polarization rotations, with spin! runs, built into a Path for queries, material spin and twist phases, sampling, and global path diagnostics. The transverse frame exposed by bishop_e1/bishop_e2/bishop_frame is the parallel-transported (Bishop) pair. This module also carries the per-segment metadata vocabulary (Nickname, MetaAdd, MetaMul). The Theory section covers the integral geometric quantities (turning angle, torsion, material twist) and the frame convention.

Bifrost.PathGeometry._ARC_BOUNDARY_TOL — Constant
_ARC_BOUNDARY_TOL

Absolute slack (metres) within which an arc length sitting at a segment boundary is attributed to the segment on its near side.

Deliberately tight, and for the opposite reason to _ARC_DOMAIN_TOL: at an interior boundary there is a competing interpretation — the next segment — and a caller who probes s_joint + δ means the far side of the joint. A boundary tolerance as loose as the domain tolerance would silently steal those queries and answer with the previous segment's geometry (a discontinuous quantity such as the bend axis then jumps by a finite angle, not an epsilon). It need only swamp the ~1e-16 relative round-off that the differing sums above introduce, which at metre scale it does by ~1e4.

source
Bifrost.PathGeometry._ARC_DOMAIN_TOL — Constant
_ARC_DOMAIN_TOL

Absolute slack (metres) allowed either side of a path's arc-length domain [0, L] before a query is rejected as off the path. Arc lengths reach a routing site through independent running sums — the segment table's entry offsets u0, a caller's own sum of segment lengths, and the ensemble remap's u_j = u0_j + τ·(u - u0_c) — whose groupings differ, so a coordinate meant for an endpoint can arrive a few ulps outside it.

Deliberately loose: past the end of the fiber there is no competing interpretation of the query, so admitting a coordinate a nanometre out costs nothing, and the alternative is rejecting a caller who reached s_end by a different sum. Contrast _ARC_BOUNDARY_TOL, which must stay tight for the opposite reason. Absolute, not relative: fibers here run 1e-2–1e3 m.

Bifrost.PathGeometry.AbstractPathSegment — Type
AbstractPathSegment

Supertype for all local-frame path segment primitives (straight, bend, catenary, helix, and the resolved cubic connector).

Each concrete segment defines its geometry in its own local frame, starting at the origin with tangent along local +z. The build placement loop rotates and chains these local descriptions into the global frame.

Implementation

A concrete segment must implement the following, where local arc length is s ∈ [0, arc_length(seg)]. The return element type T follows the segment's own type parameter (Float64 for deterministic segments, Particles for MCM-valued fields):

MethodReturns
arc_length(seg)T
curvature(seg, s)T (κ, 1/m)
geometric_torsion(seg, s)T (τ_geom, rad/m)
position_local(seg, s)length-3 AbstractVector{T}
tangent_local(seg, s)unit length-3 AbstractVector{T}
_curvature_vector_local(seg, s)length-3 AbstractVector{T} (k⃗ = dT/ds)
_parallel_transport_local(seg, v, s)length-3 AbstractVector{T}
_normal_local(seg, s)unit length-3 AbstractVector{T} (internal construction axes)
_binormal_local(seg, s)unit length-3 AbstractVector{T} (internal construction axes)
end_position_local(seg)length-3 AbstractVector{T}
_end_frame_local(seg)(T, N, B), each length-3 AbstractVector{T}

_normal_local/_binormal_local/_end_frame_local are internal geometric construction axes (they orient axis_angle, the placement chaining, and the connector boundary data). The public transverse frame returned by bishop_e1/bishop_e2 is the parallel-transported (Bishop) frame built from _parallel_transport_local.

JumpTo is unresolved: it resolves at build time into a CubicConnector.

Bifrost.PathGeometry.BendSegment — Type
BendSegment(radius, angle, axis_angle)

Circular arc of radius radius (m) sweeping angle (rad) in the plane whose inward normal is at axis_angle (rad) from the local N-axis.

In the local frame (local z = incoming tangent, local x = incoming normal, local y = incoming binormal), the inward normal direction is: n̂ = cos(axisangle)·x̂ + sin(axisangle)·ŷ

Curvature κ = 1 / radius.

Bifrost.PathGeometry.CatenarySegment — Type
CatenarySegment(a, length, axis_angle)

A catenary curve in the plane whose horizontal direction is at axis_angle from the local N-axis. a (m) is the catenary parameter (a = T₀/(ρg), the ratio of horizontal tension to weight per unit length).

The segment starts with T(0) = ẑ (framework invariant). The curvature is maximal (κ = 1/a) at the arc-length midpoint s = length/2 (the vertex), giving a symmetric curvature profile; the vertex tangent is not ẑ. The fiber deflects in the −n̂ direction (where n̂ = [cos(axisangle), sin(axisangle), 0]) as s increases. Curvature: κ(s) = a / (a² + (s − length/2)²).

Bifrost.PathGeometry.CubicConnector — Type
CubicConnector <: AbstractPathSegment

Resolved form of a JumpTo segment: a cubic Hermite curve

r(ξ) = a₀ + a₁ ξ + a₂ ξ² + a₃ ξ³,   ξ ∈ [0,1]

in 3D that matches position and tangent direction at both endpoints (G1 continuity); endpoint curvature is left free. Implements the AbstractPathSegment local-geometry interface. All connector geometry is deterministic Float64 — connectors are only ever solved from scalar boundary data.

Fields

  • a: 6 × 3 coefficient matrix; row i stores the coefficient of ξⁱ⁻¹. The curve is cubic, so the quartic and quintic rows (5 and 6) are always zero.
  • lambda: chosen handle scale.
  • s_table: arc-length lookup, where s_table[i] is the arc length from u = 0 to u = (i-1)/(n-1).
  • e1_table: n × 3 parallel-transport lookup; row i holds the local components of the transported e1 at u = (i-1)/(n-1), with e1_table[1, :] = x̂ (the entry transverse axis). Built by discrete double-reflection transport along the same u-grid as s_table.
  • twist: mechanical-twist rate (rad/m) carried from the originating JumpTo (see TwistRate).
  • meta: per-segment annotation bag (see AbstractMeta).

Bifrost.PathGeometry.HelixSegment — Type
HelixSegment(radius, pitch, turns, axis_angle)

A helix whose entry tangent is ẑ (the incoming sliding-frame tangent), ensuring continuity with the prior segment. axis_angle (rad) selects which transverse direction n̂ = cos(axisangle)·x̂ + sin(axisangle)·ŷ the helix curves toward.

The helix axis â = (h·ẑ + R·n̂) / ℓ' is tilted from the transverse plane by arctan(h/R) toward ẑ, where h = pitch/(2π) and ℓ' = √(R²+h²). This tilt is the geometric consequence of demanding tangent(0) = ẑ: a zero-pitch helix reduces to a circular arc (BendSegment) in the n̂ direction.

κ(s) = R / (R² + h²)          (constant)
τ_geom(s) = h / (R² + h²)     (constant)
arc_length = turns · 2π · √(R² + h²)

Local-frame basis vectors: n̂ = [cos(axisangle), sin(axisangle), 0] (toward helix axis) r̂₀ = [-sin(axisangle), cos(axisangle), 0] (outward radial at s=0) ê_φ = (R·ẑ - h·n̂) / ℓ' (tangential at s=0, ⊥ axis)

Bifrost.PathGeometry.JumpTo — Type
JumpTo <: AbstractPathSegment

Connector to a global target, resolved at build time into a cubic G1 Hermite CubicConnector.

The connector leaves the current position along the current tangent and lands at the global point. incoming_tangent is the global tangent direction at point; if nothing, the chord direction is used. The connector matches position and tangent at both ends (G1); endpoint curvature is left free. Both point and incoming_tangent are in the global frame, so a connector's target does not move when the segments before it change shape.

min_bend_radius (metres, nothing = unconstrained) sets a lower bound on the connector's radius of curvature: the handle scale λ grows beyond the chord default (with bisection refinement) until κ ≤ 1/Rmin. `targetlength(metres, nothing = free) fixes the connector's arc length instead, while it still lands atpoint`; with both set, λ is chosen by arc length and the radius limit is validated afterwards.

Unlike every other segment, a JumpTo with target_length = nothing and no strain meta of its own has no authored nominal length: its arc length is whatever the boundary-value solve needs to span the gap between wherever upstream placement actually lands and the fixed point. That is deliberate — the connector exists to absorb upstream geometry (bend radius, thermal expansion, tension) without the downstream target drifting, so its length is expected to change as upstream segments do. A connector that should instead hold a fixed physical length states one, either directly via target_length or by carrying its own :T_K/:tension meta, which re-solves it to that length scaled by its own strain factor.

twist is the connector's mechanical-twist rate (see TwistRate), carried onto the resolved connector.

Bifrost.PathGeometry.Path — Type
Path

Built form of a PathBuilder: its placed segments and the per-segment table that the geometry queries, the generators, the ensemble and breakpoints all read. Returned by build(::PathBuilder).

The columns are parallel arrays with one row per authored segment, in build order, zero-length segments included, never reordered or filtered after build: row c is authored segment c, and that index addresses the same authored segment in every lane scalarized from one model (see fiber/fiber-ensemble.jl).

  • seg — the PlacedSegment, connectors resolved.
  • u0, L0 — the segment's entry arc length and its (strained) arc length, L0[c] == arc_length(seg[c].segment). The finite rows tile [0, s_end] gap-free; a zero-length row is never routed to.
  • twist_entry — accumulated mechanical-twist phase at the segment entry.
  • spin_run — the row's spin run, numbered 1, 2, … along the path; consecutive rows share a run.
  • spin_rate — the run's authored rate: nothing, a Float64, or a Function of run-local material arc length.
  • spin_phi0 — accumulated spin phase at the run start.
  • spin_material0, spin_dmds — the material (unstrained) coordinate at the row entry, measured from the run start, and the slope dm/ds = 1/F for the row's glass strain factor F (1.0 unstrained). The spin phase at local arc length sl is spin_phi0 + ∫₀ᵐ rate with m = spin_material0 + spin_dmds·sl.

Bifrost.PathGeometry.PathBuilder — Type
PathBuilder(; point = (0.0, 0.0, 0.0), outgoing_tangent = (0.0, 0.0, 1.0),
              meta = AbstractMeta[]) -> PathBuilder

Create an empty path that starts at the global point heading along the global outgoing_tangent. Append segments with straight!, bend!, helix!, catenary! and the jumpto! connector, and open material-spin runs with spin!; the path ends at the exit of its last segment. meta annotates the whole path (e.g. a Nickname).

A PathBuilder is both the authoring target and the authored spec: build places it into a Path, Fiber(pb; cross_section, T_ref_K) binds it to a cross section, and FiberModel(pb; cross_section, T_ref_K) copies it into a model. Authored values may be MCM Particles in a model; build itself is scalar-only.

Example

pb = PathBuilder()
straight!(pb; length = 0.5)
spin!(pb; rate = 2π)
bend!(pb; radius = 0.05, angle = π / 2)
path = build(pb)

Bifrost.PathGeometry.PlacedSegment — Type
PlacedSegment

A segment together with its placement in the global frame: one row of a Path, whose u0 column holds the segment's entry arc length.

Records the segment, its global start origin, the 3×3 placement_frame whose columns are [N, B, T] and which transforms local vectors to global as v_g = placement_frame * v_l, bishop_e1 — the global transported (Bishop) e1 at the segment's entry, advanced segment-to-segment by _parallel_transport_local in the build placement loop — and bishop_e1_local, that entry e1 in the construction frame (placement_frame' * bishop_e1), which every transported-frame query starts from. Static arrays, so a query allocates nothing.

placement_frame is the chained geometric construction frame, distinct from the transported frame carried by bishop_e1 (the two coincide only at the path start). It is not the public bishop_frame(path, s) API. The construction frame is kept because the path-authoring DSL depends on it:

  • axis_angle is interpreted relative to the incoming local N/B construction axes;
  • bend!, helix! and catenary! placement rely on those axes;
  • connector boundary data are expressed in that local construction frame;
  • keeping this machinery means positions and tangents remain bit-identical to the old build logic.

Bifrost.PathGeometry.RotatorJonesError — Type
RotatorJonesError(unitary_deviation, det_deviation)

A rotator's Jones matrix is not in SU(2): it fails JonesMatrix(m, :is_unitary) or JonesMatrix(m, :det_is_unity), by the deviations carried here (‖J†J − I‖, worst entry, and |det J − 1|). A rotator is lossless, so a diattenuating matrix is rejected, and a global phase (det J ≠ 1) is removed by the caller, dividing J by √det J.

Bifrost.PathGeometry.RotatorSegment — Type
RotatorSegment <: AbstractPathSegment

A lossless polarization rotation applied at a point: a segment of zero length whose Jones matrix jones (a deterministic JonesMatrix in SU(2)) acts on the state arriving at it. Author one with rotator!.

The geometry is the identity: no length, curvature, torsion or twist, and the frame leaves it as it arrived. The rotation is achromatic, so it adds no phase or group delay of its own.

Bifrost.PathGeometry.StraightSegment — Type
StraightSegment{T,W} <: AbstractPathSegment

Straight line segment of signed, nonzero length along the local tangent; W is the type of its mechanical-twist rate (see TwistRate).

A negative length walks backward along the local tangent: arc_length is |length|, position advances as sign(length)·s, and the end-frame tangent/normal carry the same sign so downstream segments inherit a consistent, right-handed frame matching the direction of motion. Using sign (not a conditional) keeps this branch-free and MCM/Particles-compatible — sign broadcasts elementwise over a Particles length. length == 0 is rejected at construction (issue #344): sign(0.0) == 0.0 would otherwise give the segment a zero tangent and a zero end frame, placing every downstream segment in NaN frames.

Bifrost.PathGeometry._bend_axis_vector_at — Method
_bend_axis_vector_at(ps::PlacedSegment, s_local) -> (kx, ky)

Transverse components (k_x, k_y) = κ·(cos φ, sin φ) of the curvature vector k⃗ = dT̂/ds (1/m) in the transported frame, at physical local arc length s_local. The frame is the segment's stored entry bishop_e1 transported to s_local, which is the path's frame, continuous along the whole path by construction.

This is the un-normalized form of _bend_axis_at, and the one the birefringence terms consume. The curvature vector is transverse to the tangent, so k_x² + k_y² = κ² identically — which lets a consumer whose magnitude is polynomial in κ cancel that κ² against this pair's normalization instead of dividing by it. Polynomial in the frame components: no division, no Inf sentinel, exactly zero where the path is straight, and finite through the inflection of a connector (where κ = 0 with the segment far from straight). Conditional-free, so MCM Particles propagate through s_local.

Bifrost.PathGeometry._build_cubic_connector — Method
_build_cubic_connector(p1_local, t_hat_out;
                       min_bend_radius, target_path_length,
                       n_table, meta) → CubicConnector

Construct a CubicConnector from a JumpTo resolve. The connector is a cubic Hermite matching position and tangent at both endpoints (G1); endpoint curvature is left free.

t_hat_in is the local-frame ẑ = (0,0,1) and t_hat_out is the outgoing tangent in the same local frame.

If min_bend_radius is set, performs an exponential-bracket / bisection search over the handle scale λ until the sampled peak curvature falls below 1/min_bend_radius.

If target_path_length is set, instead searches λ until the connector's arc length matches the target — a JumpTo's target_length, which a consuming layer may stamp while the endpoint stays a lab-frame invariant.

The two constraints can be combined: when both are set, λ is chosen by the arc-length search and the result is validated against min_bend_radius.

Bifrost.PathGeometry._segment_point_budget — Method
_segment_point_budget(seg, seg_s_start, b, s_lo, s_hi, fidelity, total_len) -> Int

Return the number of sample points to allocate to the placed segment seg of the built path b, entered at arc length seg_s_start, over the clamped window [s_lo, s_hi], scaled by fidelity and the largest of four budgets: the segment's geometric turning angle, its material-spin angle, its own mechanical-twist angle, and its arc length as a fraction of total_len (the path's total arc length).

The length budget is what gives a straight, untwisted, unspun segment — zero turning angle, zero spin, zero twist, otherwise floored to just its two endpoints — a run of interior points as well, so a sampled centerline carries per-point data along its whole length rather than only at its ends. A StraightSegment raises that floor to 5 regardless of length fraction, since a short straight (e.g. a lead-in/lead-out relative to a long curved segment) would otherwise still round down to its two endpoints.

The twist budget matters even though twist_phase itself is exact (mechanical twist is a per-segment constant, integrated in closed form, never adaptively quadratured): a fast-twisting segment with negligible curvature and spin would otherwise still round down to the shared floor, leaving too few points to resolve how fast the birefringence axis is rotating — the plotted angle at each sample stays exact, but consumers that interpolate or snap between samples (e.g. inspect's cursor slider) then see that exact angle jump by several radians between adjacent points.

Bifrost.PathGeometry.build — Method
build(pb::PathBuilder; material_factors = nothing) -> Path

Place pb into the global frame and return its Path. Each segment's field-level MetaAdd/MetaMul whose symbol names one of that segment's own fields (:length, :radius, …) is applied first via _apply_field_meta — always, so authored meta is never silently dropped; meta this layer does not recognize is carried through untouched. Each jumpto! connector resolves into its CubicConnector where it is placed (see _resolve_at_placement). One placement loop runs from the start to the last segment, chaining the construction frame and transporting the Bishop frame, which is anchored at the start by _initial_frame_from_tangent and continuous along the whole path; the table rows are filled in the same pass.

material_factors holds one glass strain factor F = L_physical/L_material per segment, as a consuming layer applied them (the fiber's :T_K/:tension); it sets the spin material columns, so each segment's spin turns are conserved under strain. nothing means unstrained.

Throws an ArgumentError when pb carries MCM Particles (geometry is scalar-only; see _assert_scalar_spec), holds no segment, or material_factors does not hold one entry per segment. A failure while applying a segment's field meta or placing it is rethrown as a BuildSiteError naming that segment, with the original exception as its cause.

Extended help

Every segment defines its geometry in its own local frame, where it always starts at the origin heading along local +z. Each segment type answers two questions in local coordinates:

  1. end_position_local(seg) — where does this segment end, relative to its own start?
  2. _end_frame_local(seg) — what is the (T, N, B) frame at its end, in its own local axes?

The placement loop rotates those local answers into global coordinates and chains them (the "frame propagation" steps below). The placement_frame matrix (columns [N, B, T]) is the rotation from local to global, so placement_frame * v_local converts any local vector to global.

Two distinct frames are propagated through the loop:

  • the chained [N, B, T] construction frame (placement_frame), which interprets each segment's axis_angle and the connector boundary data — it absorbs each segment's local end frame and is internal to placement;
  • the transported (Bishop) frame e1 (with e2 = T × e1), advanced by each segment's closed-form parallel transport (_parallel_transport_local) and anchored at the path start by _initial_frame_from_tangent. This is the frame returned by bishop_e1/bishop_e2/bishop_frame.

Bifrost.PathGeometry.rotator! — Method
rotator!(pb::PathBuilder, J; meta=AbstractMeta[]) -> pb

Append a RotatorSegment to pb: a lossless polarization rotation applied, at the current point, to the state arriving there, ahead of whatever follows. It adds no length and leaves the path's position and frame unchanged.

J is the rotation in any polarization-operator representation: a JonesMatrix — Canonical.rotator, Canonical.rotator_random, Canonical.hwp — or a pure-retarder MuellerMatrix, such as axis_angle_to_mueller(axis, angle). It is stored as its SU(2) Jones matrix. A Jones matrix must already be in SU(2) (unitary, det J = 1); otherwise RotatorJonesError is thrown. A Mueller matrix carries no global phase, so its SU(2) representative is taken. A rotator is deterministic: a Particles-valued J is rejected.

Frame

J acts in the transported (Bishop) frame at the rotator: its x and y are bishop_e1 and bishop_e2 there, the frame the fiber's Jones matrix is expressed in. It does not turn with the material spin or twist of the glass.

A rotator is achromatic: it carries no phase or group delay of its own, while it rotates the differential group delay accumulated upstream. Consecutive rotators apply in author order. A rotator before the first segment acts on the launched state, and one after the last acts on the output.

See also straight!, bend!, helix!, catenary!.

Bifrost.PathGeometry.spin_rate — Method
spin_rate(path, s) -> Float64

Physical spin rate (rad/m) of a built path at arc length s: 0 where the spin run holding s has no spin, else τ_authored(m(s))·m'(s) for the run's authored rate (a constant, or a Function of run-local material arc length) at the material coordinate m(s).

Spin is material spin: the preform is rotated as the fiber is drawn, so the pattern is frozen into the glass. Thermal (:T_K) or tension (:tension) strain stretches that glass but creates and destroys no turns, so ∫ τ ds is invariant over each piece of glass. The governing transformation is the 1-form rule

τ_physical(s)·ds = τ_authored(m(s))·dm   ⟺   τ_physical(s) = τ_authored(m(s))·m'(s)

With a per-segment strain factor F_k = L_physical/L_material the map m is piecewise linear — m' = 1/F_k on segment k, the table's spin_dmds — so evaluating the authored rate at m reproduces that rule exactly, without resolving the rate into a piecewise-constant Function (which would land an adaptive quadgk over a jump discontinuity in the solver's inner loop). Unstrained, m is the run-local arc length and m' = 1.
