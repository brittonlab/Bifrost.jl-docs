Top-level plotting-wrapper entry points (dgd, phase, output) and the sweep types they return, declared at the Bifrost module level ahead of the layers that implement them.

Bifrost._BifrostMetaRegistry — Type
_BifrostMetaRegistry

Dedup table for per-segment meta (excluding Nickname, which is always shown inline) collected while a container (e.g. PathBuilder) itemizes many segments in its full display. Segments whose rendered meta text is identical share one symbolic key (meta1, meta2, ...) instead of repeating the same text once per segment; _bifrost_show_meta_registry prints the accumulated key => text lookup table once, at the end of the display.

Bifrost._Lanes — Type

Lane-major ensemble values for the solver.

An ensemble integration advances every lane — one scalar realization of an uncertain model — through one shared adaptive step sequence (docs/src/solve-workflow.md). While the solver runs, _Lanes holds the lanes' values side by side, one plain value per lane (a static 2×2 Jones matrix, or a Float64 error), so each lane's arithmetic is the scalar solver's own and an operation allocates one vector rather than one per matrix entry. The solver's kernels map over the lanes, and the step controller reduces across them with _mcm_pmax, as it reduces an MCM Particles value. The results layer turns the final lanes into Particles entries (_lanes_particles).

Bifrost._bifrost_list_compact — Method
_bifrost_list_compact([io,] v; limit = 8) -> String

Render up to limit elements of v via their own compact show, comma-separated; beyond limit, append "… (+K more)" instead of continuing to enumerate. Used for segments-style fields so a normal-sized build prints in full while a pathologically large one stays bounded.

The io form propagates any IOContext properties on io (e.g. a meta-dedup registry, see _BifrostMetaRegistry) into each element's own show call; the no-io form is a context-free convenience for use outside a Base.show method body.

Bifrost._mcm_iszero_all — Method
_mcm_iszero_all(x) -> Bool

true only when x vanishes for every particle (simply iszero for plain reals). Birefringence term guards use this instead of == zero so a zero-mean but nonzero-variance input (e.g. a signed twist rate centered on zero) is never silently collapsed to a scalar zero; a term is skipped only when it truly vanishes across the whole ensemble.

Bifrost._mcm_particle_sites! — Method
_mcm_particle_sites(x, label) -> Vector{Pair{String,Int}}
_mcm_particle_sites!(sites, x, label)

Recursively locate every Particles/StaticParticles value reachable inside x, returning label-path => particle-count pairs (e.g. "segments[2].radius" => 200).

Function values are opaque leaves: this structural walk cannot see uncertainty a function might be hiding. Two runtime checks catch that instead — _validate_model_rate_functions (an eager probe, run once at FiberModel construction) and _guarded_rate (a wrapper installed by _scalarized whenever it hits a Function during scalarize(model, i)). The eager probe catches the obvious case at authoring time; the guarded wrapper catches at solve time anything that slips past a single-point probe. The double layer is deliberate, specifically because functions are opaque to this walk.

Bifrost.dgd — Function
dgd(results::FiberPropagationResults) -> DGDSweep

Wrap propagation results for plotting: differential group delay vs the sweep's driving parameter (plot(dgd(results))). Plain data — a FiberSweep holds only the wrapped results and carries no plotting dependency of its own.

These wrapper constructors are entry points for the PlotsRecipesExt package extension (load RecipesBase or Plots alongside Bifrost to render them). Declared here, at the Bifrost top level, ahead of PathIntegral (whose results.jl supplies the real methods via import ..Bifrost: dgd), so the presentation-facing surface (this function plus phase, output, and PolarizationMath.jones) reads as one group, independent of where each wrapper type's real implementation lives.

Bifrost.inspect — Function
inspect(path; title = "", fidelity = 1.0, nsteps = 50) -> PlotlyBase.Plot
inspect(fiber::Fiber; λ_m, input_state = Canonical.H(), title = "",
        fidelity = 1.0, nsteps = 50) -> PlotlyBase.Plot

Interactive 3D inspector. inspect(path) takes a built Path: an arc-length slider scrubs a cursor along the centerline, carrying a transported T̂/N̂/B̂ frame, a normal–binormal plane, and a spin-phase arrow, alongside a live readout of s, position, curvature, geometric torsion, spin rate, and accumulated spin phase.

inspect(fiber) takes a path-backed Fiber plus λ_m and additionally shows a Poincaré-sphere inset tracking the output polarization state S(s) = stokes(J(s) * input_state) along the same slider, color-graded by arc length like the centerline.

Implemented by the PathInspectorExt package extension (load PlotlyBase alongside Bifrost to render it). Unlike dgd/phase/ output, this bypasses the plot() recipe pipeline entirely: the slider and per-step readout are Plotly-native layout/frame constructs with no RecipesBase equivalent, so plot(path) (PlotsRecipesExt) stays the static, backend-agnostic centerline view, and inspect(path) is the Plotly-only interactive diagnostic.
