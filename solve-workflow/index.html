The solve workflow

How propagate_fiber turns an uncertain FiberModel into Particles-valued optical observables. One algorithm serves every model: geometry is realized per particle with ordinary scalar code, and the optics — the expensive part — is integrated once, for all particles at once, by a single sensitivity solve. There are no execution modes and no approximation knobs. A model carrying MonteCarloMeasurements.Particles anywhere follows exactly this path; a fully deterministic model is its $M = 1$ degenerate case.

This page describes the orchestration. The physics inside the generator — what the bend, twist, ellipticity, and tension terms are and why — is derived in Deriving the Generators; the transported frame the generator is written in is defined in The transverse frame and the birefringence gauge; the path-authoring and differential-geometry layer is described in Path geometry.

The problem

An uncertain model carries Particles values — $M$ index-aligned joint samples, called particles — anywhere geometry or response inputs are authored: segment fields (radius, angle, pitch, turns, a, length, axis_angle), field-level MetaAdd/MetaMul modifiers, foreign meta payloads (:T_K, :tension), mechanical twist and spin rates, start coordinates, jumpto! connector targets, and cross-section fields. Index alignment means lane $j$ — the $j$-th sample of every Particles in the model — is one joint realization of the fiber.

The observables (Jones matrix $J$, its frequency sensitivity $G = \partial_\omega J$, DGD, common-mode phase) must be exact per particle: lane $j$ of every output equals what an ordinary scalar solve of lane $j$'s realized model produces, to solver tolerance. In particular a jumpto! connector — whose shape depends on the entire trajectory before it, which differs per particle — must be resolved from each particle's own trajectory, never from a shared or averaged one.

Two structural facts shape the solution:

  1. Uncertainty never changes the authored topology. Every particle has the same segments, in the same order and the same spin runs. Particles disagree about lengths, curvatures, frames, phases, and connector shapes — never about what exists.
  2. Geometry is cheap; propagation is expensive. Realizing a path is frame chaining plus at most a few one-dimensional connector searches. The adaptive Jones + sensitivity integration dominates the run time.

Consequence: pay the cheap part $M$ times, so that every geometric quantity is exactly its own particle's, and pay the expensive part once, by integrating all $M$ propagation problems in lockstep through one solver call.

Objects and notation

Two indices run through this page, and they are independent:

  • \[j = 1, \ldots, M\]

    — the particle (lane) index. $M$ is particle_count of the model, the number of aligned samples every Particles in it carries.

  • \[c = 1, \ldots, C\]

    — the segment index: row $c$ of the per-segment table that build puts on every Path (columns seg, u0, L0, twist_entry, spin_run, spin_rate, spin_phi0, spin_material0, spin_dmds), one row per authored segment in authored order, zero-length segments included, never reordered or filtered. $C$ is the same for every particle, because uncertainty never changes the authored topology — row $c$ is the same authored segment in every lane, so the row index is the cross-lane alignment key.

Three arc-length coordinates also appear. They are coordinates, not further indices — in particular $q$ below is a position, not something that ranges over a set:

  • \[s\]

    — physical arc length along a realized fiber, measured from its start. Every lane has its own $s$, since lanes differ in total length.

  • \[u\]

    — the reference coordinate: arc length along the nominal build, $u \in [0, L_\text{ref}]$. Shared by all lanes, and the variable the solver actually advances along.

  • \[q\]

    — segment-local physical arc length, measured from the entry of whichever segment is in play. Written $q_j$ for lane $j$'s, since a segment's physical length differs by lane.

Deterministic by contract, never Particles: the wavelength $\lambda$ (a deterministic case axis — sensitivity in $\omega$ is computed analytically through $G$), the reference temperature T_ref_K, solver tolerances (SolverParams), and function-valued rate profiles (a rate Function must return plain reals).

Stage 1 — realize the geometry, per particle

For each $j = 1 \ldots M$, build lane $j$'s fiber with the ordinary scalar machinery:

fiber_j = Fiber(scalarize(model, j))   # placement, connectors, strain — no ODE

This is a complete, independent scalar build: :T_K/:tension strain is applied once, here (including the target-length re-solve of a connector carrying its own strain), field-level meta is applied to segment fields, and one placement loop chains the construction frame, transports the Bishop frame, solves every jumpto! connector by its scalar search with min_bend_radius honored, and fills the table's spin columns. No differential equation is touched.

Because each particle's geometry is its own complete scalar build, everything downstream is per-particle correct by construction: placement frames, the parallel-transported Bishop frame (including its holonomy on non-planar paths), twist and spin phase offsets, arc lengths, and connector shapes. Nothing geometric is ever shared, averaged, or approximated across particles. The geometry layer itself stays strictly scalar — Particles never enter build (see MCM compatibility).

Failure contract. Lane feasibility is not checked in advance. Any exception raised while realizing lane $j$ — canonically a jumpto! connector that cannot satisfy min_bend_radius, or a strained connector target length shorter than its chord — is rethrown as a ParticleSolveError carrying the particle index $j$, and the calculation ends there. Lanes build concurrently, one task each, so when several lanes fail the lowest index is reported. When building one segment failed, its cause is a BuildSiteError naming that segment.

One extra build, of the nominal realization, provides the reference grid of Stage 2 and is stamped on the results for reporting and plotting.

Stage 2 — one grid for M domains

Each lane obeys its own ordinary propagation problem along its own physical arc length $s$:

\[\frac{dJ_j}{ds} = K_j(s)\,J_j , \qquad s \in [0,\ L_j] .\]

The $M$ problems live on $M$ different domains: a thermally strained segment is 0.98 m long for one particle and 1.02 m for another, so total lengths $L_j$ and every interior segment boundary sit at different $s$ per lane. A single solver call needs one domain and one set of breakpoints.

The nominal build provides both. Segment $c$ occupies $[u_{0c},\, u_{0c} + L_{0c}]$ of the reference coordinate $u$, where $L_{0c}$ is the nominal segment length, and the segments tile $[0, L_\text{ref}]$ end to end. Every particle shares this tiling, because every particle has the same $C$ segments in the same order — lanes disagree only about how physically long each segment is. Three consequences:

  • Breakpoints are shared and deterministic. Segment boundaries — the points the adaptive solver must never step across — sit at the same $u$ for all lanes and stay plain Float64.
  • Rows align by index. Row $c$ of lane $j$'s table is that particle's realization of the same authored segment as row $c$ of the nominal table.
  • A zero-length segment keeps its row, so the indices stay aligned, but its interval is empty: it adds no breakpoint and routing never lands on it.

Why nominal arc length, and not $[0, 1]$?

The reference axis is a gauge choice: any shared, monotone, lane-independent parametrization gives identical results, so $L_\text{ref}$ — and indeed the choice of the nominal realization itself — is arbitrary as far as the physics goes. Nominal arc length is chosen for four practical reasons:

  • A deterministic model reduces to the plain scalar solve exactly. With row widths taken as nominal lengths, a scalar build has $L_{0c} = A_{c}$, hence $\tau_c \equiv 1$ and $u \equiv s$. The reference machinery becomes the identity map, so a deterministic run takes the very same steps as a direct scalar solve — not merely the same answer. A normalized axis would re-parametrize every deterministic solve as well.
  • The absolute step floor stays physical. SolverParams.h_min is an absolute minimum step in units of the propagation coordinate (rtol/atol apply to the Jones matrix, and h_init/h_max default to fractions of the interval, so those are gauge-free). In metres it means the same physical floor on every fiber; on a normalized axis its physical meaning would scale with fiber length.
  • $\tau_{cj}$ keeps its meaning. As a ratio of physical to nominal segment length it is dimensionless and sits near $1$ — it is the per-segment strain, and it is the slot that carries the ensemble spread. Under a normalized axis it would instead carry the fiber's length.
  • Breakpoints, per-interval statistics, and progress reporting stay in metres, and so do any user-supplied step controls.

Stage 3 — the ensemble generator

This is the innermost method: how $M$ scalar generators become one Particles-valued generator that the standard solver integrates unchanged.

The change of variables, step by step

Work inside a single segment $c$ and a single lane $j$. Three facts set it up:

  1. Lane $j$'s segment was built with physical arc length $A_{cj}$, so its segment-local coordinate runs $q_j \in [0,\, A_{cj}]$, measured from the segment entry. The scalar term code evaluates lane $j$'s physics at $q_j$ — curvature, frame, phases — in that segment's own parametrization.
  2. The solver, however, will advance along the shared reference coordinate $u \in [u_{0c},\, u_{0c} + L_{0c}]$, which is the nominal segment's arc length.
  3. So we need a map $u \mapsto q_j(u)$ carrying the reference interval onto lane $j$'s physical interval.

Take the affine map — affine meaning a linear function of $u$ plus a constant offset, $s = \alpha u + \beta$, so the map is a uniform scaling with a shift and nothing higher order; its slope $ds/du = \alpha$ is therefore the same constant everywhere in the segment:

\[\tau_{cj} \;=\; \frac{A_{cj}}{L_{0c}}, \qquad q_j(u) \;=\; \tau_{cj}\,\bigl(u - u_{0c}\bigr) .\]

Check the endpoints: $u = u_{0c}$ gives $q_j = 0$ (segment entry), and $u = u_{0c} + L_{0c}$ gives $q_j = A_{cj}$ (segment exit). The map is increasing and bijective on the segment, so it is a legitimate change of integration variable, and

\[\frac{dq_j}{du} \;=\; \tau_{cj} \quad\text{(constant within the segment).}\]

Now re-parametrize the solution. Define $\hat{J}_j(u) = J_j\bigl(q_j(u)\bigr)$ — the same Jones matrix, read at the reference coordinate instead of the physical one. The chain rule gives

\[\frac{d\hat{J}_j}{du} \;=\; \frac{dJ_j}{ds}\bigg|_{s \,=\, q_j(u)} \cdot \frac{dq_j}{du} \;=\; \tau_{cj}\, K_j\bigl(q_j(u)\bigr)\, \hat{J}_j(u) .\]

Two things are worth stating explicitly, because they are the whole trick:

  • Nothing is stretched physically. $K_j$ is still evaluated at the true physical position $q_j$ inside lane $j$'s own built geometry. The factor $\tau_{cj}$ is the Jacobian of the coordinate change, not a modification of the physics: it accounts for the fact that one unit of $u$ covers $\tau_{cj}$ metres of lane $j$'s fibre.
  • It is exact, not an approximation. Integrating the re-parametrized equation over $[u_{0c},\, u_{0c} + L_{0c}]$ produces exactly the same segment-exit Jones matrix as integrating the original equation over $[0,\, A_{cj}]$; a change of variables cannot change the value of the solution, only the coordinate it is indexed by.

Segments concatenate cleanly. Segment $c$'s exit is segment $c+1$'s entry at the shared breakpoint $u_{0c} + L_{0c} = u_{0(c+1)}$, and $\hat{J}_j$ is continuous there, so walking the segments in order along $u$ reproduces lane $j$'s entire physical solve. The sensitivity rides along unchanged: $u$ does not depend on $\omega$, so $\partial_\omega$ commutes with the re-parametrization, and $\hat{G}_j = \partial_\omega \hat{J}_j$ obeys

\[\frac{d\hat{G}_j}{du} \;=\; \tau_{cj}\,\Bigl( K_j\, \hat{G}_j + K_{\omega j}\, \hat{J}_j \Bigr) ,\]

which is the ordinary coupled sensitivity system with the same single factor $\tau_{cj}$ in front. (This is the same reference-coordinate device the scalar solve already uses for length-changing meta — see Deriving the Generators — applied per lane.)

Worked example: a straight authored at 1.0 m, built at 0.98 m for particle 1 and 1.02 m for particle 2. The segment occupies $u \in [0, 1.0]$. At $u = 0.5$, particle 1 is evaluated at its physical 0.49 m with $\tau = 0.98$; particle 2 at 0.51 m with $\tau = 1.02$. Halfway along the reference interval is halfway through the segment for every lane, whatever its physical length — which is exactly why one breakpoint grid serves all lanes.

Stacking the lanes

Write $P_{cj}(u)$ for lane $j$'s scalar contribution in segment $c$ — the summed birefringence terms, already scaled by $\tau_{cj}$:

\[P_{cj}(u) \;=\; \tau_{cj}\, K_j\bigl(q_j(u)\bigr) .\]

Both indices are needed: $c$ says which authored segment is in play, $j$ says whose realization of it. Inside the closure $c$ is pinned by routing $u$ on the nominal grid, so only $j$ varies and the code carries $P$ as a vector over lanes.

Everything lane-dependent is prepared once, before any solving:

# One scalar build per lane, plus the nominal build that defines the reference grid.
lanes      = [Fiber(scalarize(model, j)) for j in 1:M]      # Stage 1
lane_paths = [lane.path for lane in lanes]                  # each a Path
grid       = Fiber(_nominal_realization(model)).path        # the nominal Path

Row c of lane_paths[j] is lane $j$'s realization of nominal row c of grid; the tables agree in length and order because topology is deterministic. The generator closure is then:

function ensemble_generator_K(lanes, lane_paths, grid, λ_m::Real)
    K = [generator_K(lane, λ_m) for lane in lanes]   # each lane's own scalar generator
    return function (u::Real)
        c   = _route_cell_index(grid, u)   # nominal grid: one row index for all lanes
        u0c = grid.u0[c]                   # segment entry on the reference axis
        L0c = grid.L0[c]                   # nominal segment width

        P = Vector{SMatrix{2,2,ComplexF64,4}}(undef, length(lanes))
        for j in eachindex(lanes)
            p  = lane_paths[j]                         # lane j's own Path
            τ  = p.L0[c] / L0c                         # reference → physical stretch
            uj = p.u0[c] + τ * (u - u0c)               # same fraction of lane j's row c

            # Lane j's own scalar generator, reading its own curvature, placement
            # frame, Bishop axes, spin/twist phases, and connector shape.
            P[j] = τ * K[j](uj)
        end
        return P                           # lane j's 2×2 is P[j]
    end
end

_generator_K_lanes (fiber-ensemble.jl) returns P as _Lanes, the lane-major form the solver integrates. Stacked entrywise — lane $j$'s 2×2 becoming particle $j$ of every Complex{Particles} entry — the same values are _generator_K_ensemble, the reference view.

Two details the sketch makes explicit. First, $\tau$ is computed against the nominal width L0c: a lane's own table rows take their widths from that same lane's build, so within a lane a row's width is already its physical arc length. The stretch only exists relative to the shared grid. Second, _route_cell_index returns the table-row index that addresses the matching segment in every lane; routing skips zero-length rows, so L0c > 0 and the stretch never divides 0/0.

\[K_\omega\]

is assembled identically from each lane's generator_Kω. The per-lane evaluation is the same segment-local term code the scalar solve uses, which is where per-particle exactness comes from: the ensemble generator contains no physics of its own, only routing, scaling, and stacking.

Why one call integrates M problems. The solver's kernels — the closed-form $2 \times 2$ exponential, the product with $J$, the phase-insensitive error — map over the lanes, applying to lane $j$ exactly the arithmetic a scalar solve applies. Lanes never mix, so one integration is the $M$ scalar integrations run in lockstep. Particles arithmetic is elementwise across the particle index in the same way, so integrating the Particles-valued generator gives the same bits; a test pins that. The comparisons step control needs are reduced across lanes with the _mcm_p* helpers, so no code path forks on any individual lane's value.

The one shared object is the adaptive step sequence. The step-doubling error metric (phase_insensitive_error) is reduced across lanes with a worst-lane (pmax) reduction, so each step is sized for the currently hardest particle and every lane is integrated at least to the requested tolerance.

J, G, stats = propagate_piecewise_sensitivity(K, Kω, breaks_nominal; params)

One call over the whole fiber, with J0 the identity on every lane. $J$ and $G$ come out as lanes and are stacked into Complex{Particles} entries; lane $j$'s exact Jones matrix and sensitivity are .particles[j] of every entry. See propagate_piecewise_sensitivity.

Stage 4 — observables

Observables are computed from the ensemble $(J, G)$ exactly as in the scalar workflow:

  • DGD via output_dgd_2x2 — a closed-form Hermitian eigenvalue spread of $H = -i\,J^{-1}G$, arithmetic only, hence lane-exact.
  • Common-mode phase via common_mode_phase, which consumes each lane's own physical length — evaluated per lane and stacked, like the generator.
  • The launched-state response is derived from the ensemble $J$ by plain arithmetic, so it equals the per-lane derivation entry for entry.

Results carry the nominal fiber build for reporting and plotting alongside the Particles-valued observables.

Accuracy: what "exact per particle" means

Lane $j$ of every output equals an independent scalar solve of scalarize(model, j) up to solver tolerance. The only numerical object shared between lanes is the step sequence, and it is worst-lane controlled, so sharing can only make individual lanes more accurate than their standalone solves at the same tolerance, never less.

This claim is enforced, not assumed: the gold-standard tests author a model from raw sample vectors, run the ensemble path once, and re-run every lane as an ordinary scalar build-and-solve of the same authored inputs — comparing Jones entries to $10^{-7}$ (absolute) and DGD to $10^{-5}$ (relative), lane by lane, across a topology matrix that covers every segment type, meta form, connector placement (interior, chained, strained, uncertain target), and spin/twist combination, several spin runs included.

Choosing rtol from an output accuracy

SolverParams' rtol bounds the error of each step, not of the result. Choose it from the accuracy you need at the output, measured there.

For the Jones matrix (PTF), measure the worst-case output-SOP error: the rotation angle of $J_\mathrm{ref}^\dagger J$ on the Poincaré sphere, which is the largest angle between the two outputs over every input state, mueller_to_axis_angle(mueller(JonesMatrix(...)))[2]. Against an rtol = 1e-11 reference on the 10.24 km route of issue #182 (three 30 m spools of 25 cm diameter, conduit bends, gentle transits; spin period 12 m; core axis ratio 1.02; 1550 nm; J-only):

Read the table from the requirement: a 1° PTF budget with 0.25° for the solver is met at every rtol shown, by four orders of magnitude or more; a fibre of length $L$ has the share $0.25° \cdot L / 10.24\,\mathrm{km}$. test/test_spun_fiber_closed_form.jl checks that share against the closed form of a spun straight fibre, and test/benchmark reproduces the table (run_benchmarks.jl acc full). The reference shares the solver, so the table measures convergence, not truth. The default stays 1e-9.

Cost

Relative to $M$ fully independent scalar solves, this workflow performs the same $M$ cheap geometry builds and the same total amount of generator arithmetic (each solver step does $M$-wide work), but pays the solver overhead — step-size search, interval and breakpoint bookkeeping, closure setup — once instead of $M$ times, and shares one step sequence instead of re-discovering $M$ nearly identical ones. Relative to any shared-geometry approximation, it adds only the $M$ scalar builds — and removes the approximation entirely. In wall time the two are about even: on the 1 km route of test/benchmark a 100-lane J-only ensemble costs 2.8 ms per lane, a scalar solve 2–3 ms (4-core Xeon container), each lane's own generator being most of the cost.

Design rules this workflow relies on

  • The geometry layer is scalar-only. Particles live in the FiberModel; build and every connector solver run on plain reals. Per-particle exactness comes from running that scalar machinery per lane, never from threading Particles through it.
  • Topology is deterministic. Uncertainty may change any continuous input but never segment count, order, or kind — this is what fixes $C$, makes rows align by index, and lets one breakpoint grid serve every lane.
  • Strain is applied once, at build. :T_K/:tension length changes (including connector target-length re-solves) happen inside each lane's build; the reference-grid stretch $\tau_{cj}$ then carries them into the solve exactly.
  • The propagator is branch-free and lossless. Jones factors stay in $SU(2)$; step control uses phase_insensitive_error with _mcm_p* lane reductions; no code path branches on a single lane's value; tolerances are explicit (SolverParams) rather than hidden globals.
  • Breakpoints are never stepped across, and they come from the nominal grid, shared by all lanes.

Appendix: on the three coordinate systems

Carrying $s$, $u$, and $q$ at once invites the question of whether the calculation could be done in just one of them. It cannot — but the reason is narrower than "three coordinate systems are required", and it is worth separating what is forced from what is convention.

There are three concerns, and only two of them need a live coordinate:

  1. Where the solver is. Must be shared by every lane, so that one adaptive step sequence, one interval list, and one set of breakpoints serve all of them.
  2. Where the physics is evaluated. Must be lane-specific and segment-local, because curvature, the bend axis in the Bishop frame, and the twist and spin phases are defined along one particular realized segment, parametrized from its own entry.
  3. What is physically measured. Arc length in metres — the metric in which the true equation $dJ/ds = K\,J$ is written, and in which lengths and phases accumulate.

Concerns 1 and 2 genuinely conflict: one demands a lane-independent variable, the other a lane-dependent one. No single coordinate satisfies both, which is exactly why a Jacobian appears between them.

What breaks if you pick just one

  • Physical arc length $s$ alone. Lane $j$ runs from $0$ to $L_j$, and every interior boundary sits at a different $s$ per lane, so the integration limits and the breakpoints would themselves be Particles. "One step from $s$ to $s + h$" is not well defined when the lanes disagree about where the segment ends. This forces $M$ separate solves — which is precisely the cost the workflow exists to avoid.
  • Reference coordinate $u$ alone. The domain problem disappears, but nothing can be evaluated: the physics is not a function of $u$. Recovering $K$ requires mapping to a physical position anyway. Re-expressing each lane's geometry directly in $u$ just performs that map by hand, and forfeits the reuse of the existing scalar term code that makes this design cheap.
  • Segment-local arc length $q$ alone. The same wall as $s$, one level down: the segment exit $A_{cj}$ is lane-dependent, so a shared step again has no shared endpoint. $q$ also has no global ordering of its own.

What is forced, and what is convention

The forced minimum is a lane-shared stepping variable, a lane-specific segment-local evaluation position, and the Jacobian relating them. This is the reference-element and isoparametric-map pattern familiar from finite elements: a reference domain shared by all elements, a local chart per element in which the shape functions are written, and the physical domain carrying the metric.

Three honest qualifications about how the trio appears in the implementation:

  • $s$ is not a live solver variable. It never indexes a step. It survives as the ratio $\tau_{cj}$ and as per-segment entry offsets (the table columns twist_entry for twist along physical length, and spin_material0 for spin along the material length that strain leaves invariant) for the phases that accumulate along it. It is better described as the metric being preserved than as a coordinate being traversed.
  • The globalness of $u$ is bookkeeping. The solver never steps across a breakpoint; it already restarts at each one. A single global $u$ axis is therefore just $C$ per-segment reference intervals concatenated so the propagator sees one breaks vector and one running $(J, G)$. Solving segment by segment on a shared $[0, 1]$ and composing by matrix product would be the same mathematics with more plumbing.
  • $q$ could be narrowed. If segment-shape queries took a normalized position rather than a physical one, $u$ could map straight to a fraction of the segment and $q$ would drop out of those queries entirely. Quantities that accumulate per unit length — twist rate times length, spin phase, the $\beta$ integral behind common_mode_phase — still need metres, so $q$ would narrow rather than vanish.
